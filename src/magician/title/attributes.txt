;   The title screen's 64 attribute bytes -- 4 rows of 16. They start at $23C0,
;   which is why a full scene is 960 + 64 bytes and not 960.
;
;   A byte is four 2-bit quadrant selectors: bits 0-1 choose a sub-palette for the
;   left half of a 4x4 tile block, 2-3 the right, 4-5 the top, 6-7 the bottom.
;   Every one of the 256 byte values is therefore in range by construction -- there
;   is no out-of-range attribute to catch -- but the *choice* is what paints the
;   screen, and getting it wrong recolours the logo without any error.
;
;   These are the attribute bytes that belong to the tile grid above, unchanged
;   from Eurocom's own data. They are what put the brick in one sub-palette, the
;   logo outline in another, the figures green and the moon blue, and they are
;   keyed to fixed 4x4 blocks of the screen -- which is why the artwork cannot be
;   slid up or down without recolouring it. The four sub-palettes are fixed by
;   TIT.PAL (12 bytes = 4 sub-palettes x 3 colours) and a BizHawk run of the
;   cartridge reports exactly that in PALRAM: 0F 28 38 30 0F 2A 3A 30 0F 17 27 38
;   0F 21 31 30.
