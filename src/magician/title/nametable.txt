;   The title screen's tile grid -- 32 x 30, one row of 32 hex bytes per line.
;
;   THIS IS THE SOURCE. The packed .DAT that TITLE.SRC emits is generated from
;   this file by tools/datcodec.py on every build (asm/build.py:pack_our_scenes)
;   and is never committed, so this grid is the only copy of the screen.
;
;   ------------------------------------------------------------------
;   WHERE THESE BYTES COME FROM
;   ------------------------------------------------------------------
;   They are Eurocom's own. `vendor/Magician-NES/DAT/TIT.DAT` is 314 packed
;   bytes; tools/datcodec.py expands it to 960 tile bytes + 64 attribute bytes;
;   this file is that expansion, one row per line.
;
;   The expansion is lossless in the direction that matters: re-packing this grid
;   with the same token ($E0) reproduces `DAT/TIT.DAT` **byte for byte**, which is
;   asserted on every build. So this file is a readable view of the shipped
;   asset, not an interpretation of it, and nothing about it is ours.
;
;   Until 2026-10-05 it was not. This grid was hand-authored -- derived by
;   observing the *release* cartridge and reproducing what it appeared to show,
;   because every "the title data is absent" measurement in this project had been
;   taken against the release, and the release genuinely does not contain
;   TIT.DAT. Measured in BizHawk at frame 60 against **beta1**, that
;   reconstruction matched Beta 1's nametable for 27 of 30 tile rows and was
;   wrong across the whole of the bottom three: Beta 1 has real tiles there
;   ($B0 $93 $94 $95 $96 $B1 $B2 ...) and the reconstruction had a solid $08
;   backdrop. Palette, attributes and the in-use pattern table already matched
;   exactly; only the grid was invented.
;
;   With these bytes the same measurement is **1024/1024 on the nametable,
;   4096/4096 on all of CIRAM, 32/32 on the palette, 64/64 on the attributes and
;   8192/8192 on the pattern table in use** -- see README.md.
;
;   Nothing else in src/magician/ needed to change to get there: the packing
;   pipeline, the token, the size budget against `pwdat`, the read-back through
;   the assembled image and the tools/titletest.py fail-check gate were all
;   already right. Only the content was wrong.
